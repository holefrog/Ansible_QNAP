# Ansible_QNAP

本项目是家庭实验室（Homelab）的**后端基础设施层**。基于 Ansible 自动化架构，专门针对 QNAP NAS 的 Container Station 部署核心级容器服务。

该项目作为独立的服务提供者（Provider），为其他项目（如家庭各房间客户端设备）提供强解耦的数据支撑和凭证下发。

---

## 1. 项目目标与设计理念

1. **服务提供者定位（Provider）**：
   专注做好后端数据中枢，不与前端播放设备（电视盒子、音箱、平板等）的逻辑混杂，通过统一的凭证和网络接口对外赋能。
2. **全局路径解耦**：
   彻底杜绝代码中硬编码绝对路径。底层的存储卷（如 `qnap_vol1`、`qnap_vol4`）和统一的基础目录，全部集中在 `group_vars/qnap.yml` 中维护。迁移至新磁盘或全新 NAS 时，仅需修改一处变量即可全局适配。
3. **凭证隔离自动化导出**：
   部署 MariaDB 后，脚本会自动向控制节点的 `~/.config/homelab/mariadb_config.yml` 导出安全凭证。前端客户端项目（如 Kodi）直接读取该共享凭证自举连接，无需在代码中硬编码密码。
4. **前置环境优雅拦截**：
   充分适配 QNAP QTS 系统的特性。针对需通过 App Center 手动安装的 Container Station，提供环境探测拦截机制，给出直观引导而非生硬报错。

---

## 2. 核心功能

| 服务组件 | 核心功能 | 服务定位与对外能力 |
| :--- | :--- | :--- |
| **MariaDB** | 集中媒体数据库 | 为 Kodi 等客户端提供统一刮削元数据、海报墙与多终端断点续播，支持跨项目凭证自动下发。 |
| **LMS (Lyrion)** | 集中流媒体音乐服务器 | 为全屋 Squeezelite、WiiM、AirPlay 音频终端提供高保真音频流分发，采用 Host 网络栈实现零配置多播发现。 |

## 3. 如何使用

### 3.1 准备凭证（仅首次）
1. 进入 `ansible/` 目录，基于模板创建机密变量文件：
   ```bash
   cp secrets.yml.example secrets.yml
   ```
2. 填入您的 QNAP 登录凭证与数据库密码（强烈建议使用 `ansible-vault` 加密）。

### 3.2 一键交互式部署与日常运维
在 `ansible/` 目录下运行交互式导航脚本：

```bash
cd ansible/
./apply.sh
```

**菜单功能说明：**
- **`1. 🚀 全部部署`**：首次上架运行。依次检测基础环境 -> 部署 MariaDB -> 部署 LMS -> 自动导出跨项目凭证。
- **`2. 🐳 仅部署 Docker 基础环境`**：用于新 NAS 初始化，检查 Docker 版本并创建必备存储目录。
- **`3. 🗄️ 仅部署 MariaDB`**：专门用于强制重置数据库配置及重新下发跨项目凭证。
- **`4. 🎵 仅部署 LMS`**：日常一键无感升级 LMS，自动拉取新镜像、校验变更并平滑重建容器。
- **`5. 🔍 检查所有服务状态`**：全机健康看板，集中输出所有容器运行时间与底层挂载目录存在性。

- 📗 **[Docker_Mariadb.md](documents/Docker_Mariadb.md)**：MariaDB 集中数据库设计、权限修复（UID 999）、Kodi 数据库版本映射表（Omega / Piers）与跨大版本数据迁移指南。
- 🎵 **[Docker_LMS.md](documents/Docker_LMS.md)**：LMS 容器技术规格、Host 网络模式选型原理（广播 UDP 3483 穿透与消灭 172 网桥推流死链）、音源只读挂载规范与播放器接入排错。
